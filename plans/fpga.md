# FPGA 方向培养方案

[返回总导航](../README.md)

本方向从数字逻辑和 RTL 设计出发，通过仿真、定点参考模型、时序分析和板级验证建立完整工程能力。第一阶段仅使用 PL，后续再学习 PS、AXI、DMA 和软硬件协同。

## 培养目标

FPGA方向面向数字系统设计、实时信号与图像处理、硬件加速和软硬件协同研究。学生应建立RTL设计思维，掌握Verilog或SystemVerilog、仿真验证、时序分析、片上存储、常用接口和流水线设计，能够将算法转化为可验证、可综合并满足时序要求的硬件系统。

## 学习路线

数字逻辑  →  Verilog与RTL设计  →  仿真与自动验证  →  第一阶段综合项目  
时序与CDC  →  FIFO与片上资源  →  AXI与软硬件协同  →  信号图像处理与科研项目

## 建议训练平台

建议统一使用Xilinx Zynq-7020开发板。第一阶段仅使用PL部分完成纯FPGA设计，后续再进入PS、AXI、DMA和Linux环境。若实验室已有Artix-7平台，可保持相同培养内容，软硬件协同部分另配Zynq平台完成。

## 第一阶段综合项目

### 项目名称

基于FPGA的可配置多通道信号采集与实时处理系统。

### 项目目标

学生在PL端独立完成数据输入、通信协议、缓存、实时滤波、特征计算和结果回传，并使用Python建立定点参考模型和自动化测试程序。第一阶段不使用Zynq PS、AXI和厂商FIR IP核。

### 系统流程

内部信号 UART数据 SPI ADC  →  数据选择与协议解析  →  FIFO与BRAM  
→  滑动平均与FIR流水线  →  特征计算  →  UART回传  →  Python验证

### 主要功能

| 模块 | 项目要求 |
| --- | --- |
| 数据源 | 支持内部正弦波、方波、三角波和伪随机噪声，支持UART输入，并连接双通道12位SPI ADC扩展模块 |
| 通信协议 | 设计帧头、命令、数据源、长度、参数、数据和CRC-16，支持参数设置、启动停止及状态读取 |
| 数据缓存 | 独立实现接收FIFO、处理FIFO、发送FIFO和BRAM循环缓存，具有满空、溢出和错误统计 |
| 处理模式 | 支持原始数据直通、滑动平均滤波和不少于16阶的可配置定点FIR滤波 |
| 定点处理 | 明确Q格式，处理乘加、位宽增长、截位、舍入、溢出和饱和 |
| 特征计算 | 实时计算最大值、最小值、均值、峰峰值、均方根值、过零次数和阈值越界次数 |
| 事件响应 | 超过阈值时点亮LED，记录异常位置并向上位机发送状态帧 |
| Python端 | 完成信号生成、串口协议、CRC、定点参考模型、波形频谱绘制和自动误差比较 |

### 设计要求

- 核心FIFO、通信控制和FIR模块由学生自行设计，不直接调用同类厂商IP核。

- 所有模块使用统一的valid、ready或明确的数据有效控制，不依靠固定延时拼接系统。

- 先完成模块级验证，再进行系统级仿真和板级测试。

## 验证内容

| 验证层级 | 验证要求 |
| --- | --- |
| 模块验证 | 验证UART、SPI ADC、FIFO、BRAM、CRC、FIR、特征计算、复位和异常状态 |
| 边界验证 | 覆盖最大最小值、FIFO近满、错误CRC、残缺数据帧、运行中复位和参数动态修改 |
| 随机验证 | Python产生随机幅值、频率、噪声和长度，自动比较FPGA与定点参考模型 |
| 板级验证 | 使用ILA观察数据链路，使用示波器或逻辑分析仪检查串口、SPI、时钟和有效信号 |
| 时序验证 | 建立完整时钟约束，检查关键路径、跨时钟路径、WNS和未约束路径 |

## 验证原则

测试程序必须自动输出通过或失败，不能只依靠人工观察波形。Python参考模型应使用与RTL一致的定点位宽、舍入和饱和规则。

## 第一阶段项目验收指标

| 验收项 | 最低要求 |
| --- | --- |
| 工作时钟 | 完成100 MHz时钟约束，WNS不小于0，无未约束关键路径 |
| 数据位宽 | 输入和输出数据位宽不低于16 bit，定点格式说明完整 |
| UART | 115200 bit/s基本验收，提高项达到921600 bit/s |
| ADC | 双通道SPI ADC能够连续采样，采样率不低于100 kS/s每通道 |
| FIR | 不少于16阶，系数可配置，处理结果与Python定点模型逐点一致 |
| 处理吞吐 | FIR稳态吞吐率不低于每时钟1个采样，给出总处理延迟 |
| BRAM缓存 | 能够循环保存并回传不少于4096个采样点 |
| 特征计算 | 最大值、最小值、均值、峰峰值和均方根值计算正确 |
| 连续通信 | 连续处理不少于10万组输入数据，无丢失、重复和乱序 |
| 异常处理 | 错误CRC、FIFO溢出和残缺数据帧能够识别并恢复 |
| 自动测试 | cocotb或自检Testbench能够自动判断通过或失败 |
| 稳定运行 | 系统连续运行不少于2小时，无死锁和异常停止 |
| 工程分析 | 提交资源占用、关键路径、最高频率、延迟和吞吐率分析 |

## 算法硬件化与研究方向

学习FIR、FFT、卷积、滤波、边缘检测、图像缩放和数据格式转换的硬件实现，重点分析定点精度、流水线、存储访问、带宽、资源、延迟和吞吐率。后续可进入实时偏振图像预处理、Stokes参数计算、双目视觉前端、图像融合及视觉算法加速等课题。

## 验收前需明确的工程参数

原方案的量化指标保持不变，实施时应由方向负责人明确以下测试口径并写入项目规格。

- 双通道 ADC 每通道 100 kS/s 与 UART 波特率是不同链路的指标；全速原始数据不能直接经低速 UART 持续回传，应明确实时处理、BRAM 缓存、批量回传或降采样的工作模式。
- FIR 的“阶数”和抽头数应在规格中统一，明确系数个数、Q 格式、舍入及饱和规则。
- 每时钟一个采样的稳态吞吐率按 FIR 内核验收；需分别报告采集速率、内核吞吐和端到端传输速率。
- 均值、均方根和事件统计应明确窗口、误差判据及复位行为；逐点一致要求按同位宽定点参考模型验证。
